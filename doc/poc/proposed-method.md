## 1. 目的

次のパイプラインが、着順分布として整合し、展開シナリオを入れたときに順位が想定方向へ動くことを検証する。

```
LightGBM
  ↓
各馬の utility
  ↓
展開シナリオ（slow / average / high）
  ↓
Plackett-Luce
  ↓
Monte Carlo
```

この PoC で固定する具体化は次の 4 点である。図の各段を、テストできる式に落とすために置く。

| 項目 | 内容 |
|------|------|
| utility | LightGBM の素点を温度 `T` で割った、そのレース限りの値。馬の恒久的な能力そのものではない |
| シナリオ確率 | メンバーから `p(s \| field)` を出す。比率は固定値にしない |
| 脚質補正 | `δ(脚質, シナリオ)` を検証データで推定する |
| Monte Carlo | Plackett-Luce 混合からのサンプルであり、能力へ乗せる二段目のノイズではない |

1 着確率は混合 softmax の閉形式で出す。Monte Carlo は 3 着以内、平均着順、連対以下の組み合わせに使う。

タイム、着差、再生フレームは既存手法の出力であり、この PoC の合格条件に含めない。

## 2. 分布

シナリオ `s` のもとで、馬 `i` の utility を `u_i(s)` とする。順位 `π` の確率は次のとおり。`π_k` は k 位の馬である。

```
P(π | s) = Π_{k=1}^{n-1}  exp(u_{π_k}(s)) / Σ_{j=k}^{n} exp(u_{π_j}(s))

P(π) = Σ_s  p(s | field)  P(π | s)
```

1 着確率は順位を周辺化して次になる。

```
P(i が 1 着 | s) = exp(u_i(s)) / Σ_j exp(u_j(s))

P(i が 1 着) = Σ_s  p(s | field)  P(i が 1 着 | s)
```

utility の共通の加算は確率を変えない。全馬の utility を定数倍すると確率が変わる。そのスケールを吸収するのが温度 `T` である。

```
u_i(s) = f(x_i) / T + δ(style_i, s)
```

`f(x_i)` は LightGBM の素点、`x_i` はその馬とレースの特徴である。`δ` はシナリオと脚質の表で、average の列は 0 に固定する。枠の効果は `f` 側の特徴として学習させ、`δ` には入れない。

## 3. シナリオ

シナリオは slow、average、high の 3 値とする。過去レースでは前半速度からラベルを付けられる。この PoC の合成データでは、生成時に使ったシナリオをラベルにする。

予測時にはシナリオは未知なので、出走表から分布を出す。

```
nFront = 脚質が front の頭数

logit(slow)    = 0.80 - 0.60 * nFront
logit(average) = 1.00
logit(high)    = -0.40 + 0.70 * nFront

p(s | field) = softmax(logit)
```

上の係数は合成データの生成真値である。学習側は同じ特徴 `nFront`、距離、馬場で多項ロジスティック回帰を当て、真値の係数は与えない。

生成真値での確率は次のとおり。

| nFront | p(slow) | p(average) | p(high) |
|--------|---------|------------|---------|
| 0 | 0.396417 | 0.484185 | 0.119398 |
| 1 | 0.230909 | 0.513897 | 0.255194 |
| 2 | 0.109765 | 0.445118 | 0.445118 |
| 4 | 0.014480 | 0.194952 | 0.790568 |

`nFront` が増えると high が増え、slow が減る。

脚質補正の生成真値は次のとおり。

| シナリオ | front | stalk | mid | closer |
|----------|-------|-------|-----|--------|
| slow | +0.30 | +0.12 | 0.00 | −0.22 |
| average | 0 | 0 | 0 | 0 |
| high | −0.22 | −0.08 | +0.10 | +0.30 |

単一シナリオで、素点を足した utility が逃げ・差し・追込でいずれも 1 のときの 1 着確率は次のとおり。

| シナリオ | 逃げ | 差し | 追込 |
|----------|------|------|------|
| slow | 0.413834 | 0.322294 | 0.263872 |
| high | 0.255221 | 0.344512 | 0.400266 |

high では追込の 1 着確率が逃げを上回る。slow では逆になる。P3 はこの表と一致することを見る。

## 4. 学習

### 4.1 特徴

使う特徴は、速度、スタミナ、加速、コーナリング、脚質、芝適性、ダート適性、適性距離とレース距離の差、斤量、騎手 skill、枠番、`nFront`、距離、馬場、馬場状態である。

当該レースの着順、着タイム、上がり、オッズ、人気は入れない。特徴リストをテストで検査する（P9）。

### 4.2 LightGBM と温度

PoC の `f` は、馬ごとの二値分類（その馬が 1 着かどうか）で学習した LightGBM の素点とする。行を独立とみなすので、素点の softmax はレース内の確率として校正されていない。検証レースで温度 `T > 0` を 1 次元探索し、勝者の対数損失を最小にする。

```
p_i = softmax(f(x_i) / T)    // シナリオ補正の前の基準点
```

シナリオを含む最終的な 1 着確率は 2 節の混合である。`T` の探索は、`δ` を同時に置いた混合確率の対数損失に対して行う。

参照推定として、同じ特徴の線形 softmax 回帰（条件付きロジット）を同じ分割で学習する。合成データの真の utility が線形なので、この参照が LightGBM より悪いときは特徴か分割の不具合を先に疑う。LightGBM が参照より悪いこと自体は、線形な生成過程では失敗にしない。失敗にするのは null を下回れない場合と、シナリオを外すと損失が改善してしまう場合である。

### 4.3 δ とシナリオ確率

`δ` は脚質 4 × シナリオ 3 の加算で、average の 4 マスは 0 に固定し、残り 8 個を検証レースの Plackett-Luce 対数尤度で推定する。実装は格子探索でも、脚質×シナリオのダミーを持つ線形モデルでもよい。

シナリオモデルは 3 節の特徴を持つ多項ロジスティック回帰とし、訓練レースのシナリオラベルを当てる。テスト時は予測分布 `p(s | field)` で混合する。テストラベルのシナリオで条件付き評価した損失は診断として残し、合格判定は未知シナリオの混合確率で行う。

### 4.4 分割

合成データはレース ID 単位で訓練 60%、検証 20%、テスト 20% とする。同一レースの馬を分割の両側に置かない。

実データを使う場合は日付で切り、訓練日より後のレースだけを検証とテストに置く。馬や騎手の過去成績を特徴へ足す場合も、そのレースより前のレースだけを集計する。

seed は `20261018`。LightGBM の `random_state` もこの値にする。

## 5. サンプリング

1 着確率の報告値は 2 節の閉形式である。サンプル頻度を 1 着確率の報告値にはしない。

3 着以内確率と平均着順は、次の手順で M 回引いて推定する。既定の M は 20,000 である。

1. 検証用 PRNG からシナリオ `s` を `p(s | field)` で引く
2. 各馬に独立な Gumbel ノイズ `E = -log(-log(U))` を足す。`U` は (0, 1) の一様乱数
3. `u_i(s) + E_i` の降順をその試行の着順とする

この手順の順位分布は、そのシナリオの Plackett-Luce と一致する。残っている馬から utility の softmax で 1 頭ずつ選ぶ逐次法と同じ分布である。P1 では両方を実装し、頻度が許容差に入ることを見る。

サンプル用の乱数は既存手法 7 節の `mix` と mulberry32 を使う。チャネル 2 をシナリオ、チャネル 3 を Gumbel に割り当て、試行番号を `trialIndex` に入れる。能力の `multiplier` は掛けない。

`top3Prob` は着順が `min(3, n)` 以内だったサンプルの割合、`meanRank` はサンプル着順の平均とする。サンプル平均の `top3Prob` を馬について合計すると `min(3, n)` に近づく。

## 6. 機構テストの厳密値

4 頭の utility を `2, 1, 0, -1` とする。単一シナリオ、温度適用済みの値である。全順列 24 通りを 2 節の式で足すと、周辺確率は次になる。

| 馬 | utility | P(1着) | P(2着) | P(2着以内) | P(3着以内) |
|----|---------|--------|--------|------------|------------|
| A | 2 | 0.643914 | 0.282677 | 0.926592 | 0.993924 |
| B | 1 | 0.236883 | 0.458817 | 0.695700 | 0.948214 |
| C | 0 | 0.087144 | 0.187521 | 0.274666 | 0.757393 |
| D | −1 | 0.032059 | 0.070984 | 0.103042 | 0.300469 |

順位 A, B, C, D の確率は 0.313155 である。1 着確率の和は 1、2 着以内確率の和は 2、3 着以内確率の和は 3 である。

M = 20,000 のとき、確率 0.64 付近の標準誤差は約 0.003 である。許容差 0.02 は、壊れたサンプラ（除外し忘れ、昇順の取り違え、Gumbel の符号反転）を落とす幅であり、偶然の失敗はほぼ起きない。

## 7. 合成データ

### 7.1 規模

レース数 4,000。頭数は 8 以上 14 以下の一様整数。分割は 4.4。生成 seed は `20261018`。乱数は NumPy の `default_rng` を使い、レース ID の昇順に、頭数、各馬の属性、シナリオ、着順の順で消費する。

### 7.2 生成

各馬の属性は次の順に引く。正規乱数は標準正規、範囲外は切り詰める。

| 属性 | 分布 |
|------|------|
| speed, stamina, acceleration, cornering | `clip(50 + 12 z, 30, 95)` |
| jockey.skill | `clip(50 + 15 z, 20, 95)` |
| weight | `clip(55 + z, 51, 60)` を小数 1 桁 |
| runningStyle | 4 脚質を等確率 |
| gate | 1..n の無作為な順列 |
| aptitudes | 中立。`turf = dirt = 1`、`bestDistance` はレース距離 |
| course | 距離は 1,200 / 1,600 / 2,000 を等確率。馬場は芝 2、ダート 1 の比率。going は good |

レースのシナリオは 3 節の `p(s | nFront)` から 1 つ引く。馬の utility は次のとおり。

```
u_i(s) = 0.035 * (speed - 50)
       + 0.015 * (stamina - 50)
       + 0.012 * (jockey.skill - 50)
       - 0.020 * (weight - 55)
       - 0.015 * (gate - 1)
       + δ(style_i, s)
```

着順は、この `u_i(s)` に Gumbel を足した降順とする。保存するのは属性、シナリオラベル、着順であり、utility の数値は保存しない。学習側は着順と属性だけを見る。

`dgp-sim` 用に属性だけが必要なときは、同じ手順で属性まで引き、シナリオと着順の乱数は消費しない。着順は既存手法のシミュレータが付ける。

## 8. 検証項目

| ID | 操作 | 合格 |
|----|------|------|
| P1 | 6 節の 4 頭を、Gumbel 法と逐次法で各 M = 20,000 | 各馬の 1 着・2 着以内・3 着以内の頻度が表と絶対差 0.02 以内。順位 A→B→C→D の頻度が 0.313155 と絶対差 0.02 以内 |
| P2 | 頭数 8、シナリオ確率を任意の内点、utility を任意 | 閉形式の 1 着確率の和が 1 ± 1e-12。各サンプルは 3 頭を 3 着以内に持つので、top3Prob の和は 3 ± 1e-9 |
| P3 | 3 節の逃げ・差し・追込の単一シナリオ | 1 着確率が表と絶対差 1e-6 以内。high の追込が逃げより高く、slow では逆 |
| P4 | 同一 utility で `p(high) = p(slow) = 0.5`、average は 0 | 混合 1 着確率が、二シナリオの 1 着確率の算術平均と絶対差 1e-12 以内 |
| P5 | 7 節のデータで `T` と `δ` とシナリオモデルを学習する | テストの winner log loss が、そのテスト集合の null より小さい |
| P6 | P5 のモデルから `δ` とシナリオ混合を外し、温度付き softmax だけにする | 完全モデルのテスト対数損失が、外したモデルより小さい |
| P7 | P5 で推定した `δ` と `p(high)` | `δ(closer, high) > 0`、`δ(front, high) < 0`、`δ(closer, slow) < 0`、`δ(front, slow) > 0`。`nFront = 4` の平均予測 `p(high)` が、`nFront = 1` のそれより 0.20 以上大きい |
| P8 | P5 の閉形式 1 着確率と、M = 20,000 の 1 着頻度を、テストから無作為に 30 レース比べる | 全馬の絶対差の平均が 0.008 未満、最大が 0.03 未満。サンプル側だけで確率を作っていないこと |
| P9 | 学習に渡す特徴名を列挙する | 4.1 の禁止列が一つも無い |

P6 は、展開シナリオが合成データの着順に寄与していることを、予測の損失で確認する。P7 は、その寄与の向きが 3 節の表と一致することを確認する。P8 は、Monte Carlo が分布の推定器であり、別の実力ノイズではないことを確認する。

実データがある場合は、同じ実装で winner log loss、Brier、ECE、低勝率帯（予測勝率 0.05 未満）の top3 較正差を記録する。Plackett-Luce は 2 着以下で人気馬を厚く見積もることがある。この差は記録項目とし、合成データの合格条件にはしない。実データが無い PoC は P1〜P9 で判定する。

## 9. 合格

P1〜P9 が合格であること。PoC 計画の X2 では、`dgp-sim` に対するテスト対数損失が null を下回ること。

学習のビット一致は求めない。要求するのは、指定 seed で P5〜P7 の不等式が再現することと、推論サンプルが P1 と P8 の許容差に入ることである。

## 10. 既存手法との分担

| 出力 | 既存手法 | 提案手法 |
|------|----------|----------|
| 勝率、3 着以内率、平均着順 | Monte Carlo 集計 | 1 着は閉形式、他は Plackett-Luce のサンプル |
| 着タイム、着差、通過順、フレーム | tick の状態 | この PoC では出さない |
| ペース | 先頭速度から創発し、脚質係数を掛ける | メンバーからシナリオ確率を出し、utility を混合する |
| 馬同士の接触、枠のロス | ブロックと進路延長 | utility の特徴と `δ` に含まれる範囲 |

同じ出走表に対して両方の確率を並べて記録してよい。既存手法の tick の中で、さらに Plackett-Luce のノイズを掛けない。不確実性を二度数えることになる。

## 11. この PoC で見ないもの

- 実在タイムへの速度係数の校正
- 馬連・三連単の市場比準。サンプルから確率は作れるが、合格基準は 1 着と 3 着以内に置く
- 提案手法のサンプル経路を、既存手法の再生フレームとして描くこと
